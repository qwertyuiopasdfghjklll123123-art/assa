# سُفرة — تطبيق طلبات مطعم (لوحة مستخدم + لوحة أدمن)

تطبيق ويب عربي (RTL) لطلب الطعام، مبني بـ **Next.js 16 + React 19 + Tailwind CSS 4**، مع **Firebase** كقاعدة بيانات ونظام تسجيل دخول.
الألوان: برتقالي، أبيض، وسماوي. الخطوط: IBM Plex Sans Arabic و Tajawal.

## الصفحات

**لوحة المستخدم**

| الصفحة | المسار | الوصف |
|---|---|---|
| الرئيسية | `/` | ترحيب، اختيار الفرع، بطاقة عرض الولاء، رصيد النقاط، الأكثر طلباً، الفروع |
| المنيو | `/menu` | أقسام وبحث، إضافة للسلة، الأصناف غير المتوفرة |
| السلة | `/cart` | الكميات، توصيل أو استلام، العنوان والهاتف، استخدام النقاط كخصم، تأكيد الطلب |
| طلباتي | `/orders` | فلترة حسب الحالة، تفاصيل الطلب وخط سير الحالة، إلغاء الطلب المنتظر |
| الولاء | `/loyalty` | الرصيد، التقدم نحو المكافأة، الإحصائيات، شرح البرنامج |
| حسابي | `/account` | تعديل البيانات، الإشعارات، اتصل بنا، حول التطبيق، تسجيل الخروج، حذف الحساب |
| الدخول | `/login` `/register` `/forgot` | بريد وكلمة مرور، جوجل (مع Firebase)، واتساب |

**لوحة الأدمن** (`/admin`، لحساب الأدمن فقط)

| الصفحة | الوصف |
|---|---|
| نظرة عامة | طلبات اليوم، الطلبات النشطة، المبيعات، العملاء، رسم بياني لآخر 7 أيام، الأكثر مبيعاً |
| الطلبات | فلترة وبحث، تغيير الحالة بنقرة (مؤكد ← قيد التحضير ← في الطريق ← تم التسليم)، رفض/إلغاء، يصل إشعار للعميل تلقائياً |
| المنيو | إضافة/تعديل/حذف الأقسام والأصناف، رفع الصور، السعر، التوفر، التمييز |
| الفروع | إضافة/تعديل الفروع، فتح/إغلاق الفرع |
| المستخدمون | البحث، تعديل النقاط، إرسال إشعار خاص، منح/سحب صلاحية الأدمن، الحظر، سجل الطلبات |
| الإشعارات | إرسال إشعار لجميع العملاء |
| الإعدادات | اسم المطعم، رسوم التوصيل، الحد الأدنى، نسبة الولاء وقيمة النقطة، معلومات التواصل |

**النقاط:** عند تحويل الطلب إلى «تم التسليم» يحصل العميل على نسبة (افتراضياً 5%) من قيمة الطلب كنقاط. عند إلغاء طلب استُخدمت فيه نقاط تُعاد النقاط للعميل.

## التشغيل

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # يُخرج موقعاً ثابتاً في مجلد dist
```

### الوضع التجريبي (بدون أي إعداد)
إذا لم تُضبط متغيرات Firebase يعمل التطبيق بقاعدة بيانات داخل المتصفح (localStorage) مع بيانات تجريبية.
حساب الأدمن التجريبي: `admin@sufra.app` / `admin123`.
هذا الوضع للتجربة فقط: البيانات لا تُشارك بين الأجهزة.

### الإنتاج مع Firebase
1. أنشئ مشروعاً في [Firebase Console](https://console.firebase.google.com) وفعّل:
   **Authentication** (Email/Password و Google)، و**Firestore**، و**Storage**.
2. انسخ `.env.example` إلى `.env.local` واملأ القيم من إعدادات تطبيق الويب.
3. انشر قواعد الحماية: `firebase deploy --only firestore:rules,storage`
4. **إنشاء حساب الأدمن:** سجّل حساباً عادياً من صفحة `/register`، ثم في Firestore افتح
   `users/{uid}` لهذا الحساب وغيّر الحقل `role` من `user` إلى `admin`.
   بعدها يستطيع هذا الأدمن منح الصلاحية لآخرين من صفحة المستخدمين.
5. أضف الفروع والأقسام والأصناف من لوحة الأدمن، واضبط الإعدادات.

## النشر
`npm run build` ينتج موقعاً ثابتاً في `dist/` يمكن رفعه إلى أي استضافة (Hostinger، Firebase Hosting، Netlify…).
متغيرات `NEXT_PUBLIC_FIREBASE_*` يجب أن تكون موجودة **وقت البناء**.
أو باستخدام Docker:

```bash
docker build -t sufra . && docker run -p 3000:3000 sufra
```

## بنية الكود

```
src/
  app/(shop)/      صفحات المستخدم
  app/(auth)/      الدخول والتسجيل
  app/admin/       لوحة الأدمن
  components/      المكونات المشتركة (الواجهة، السلة، المصادقة)
  lib/backend/     طبقة البيانات: firebase.ts (إنتاج) و local.ts (تجريبي)
  lib/services.ts  منطق الطلبات والنقاط والإشعارات
  lib/models.ts    أنواع البيانات والإعدادات الافتراضية
firestore.rules    صلاحيات Firestore (الأدمن يتحكم بكل شيء، العميل ببياناته فقط)
```

> ملاحظة أمان: الأسعار تُحسب في المتصفح. قواعد Firestore تمنع العميل من رفع نقاطه أو تغيير صلاحياته أو حالة الطلب، لكن الأدمن يجب أن يراجع قيمة الطلب قبل تأكيده. للتحقق الكامل من الأسعار على الخادم يمكن لاحقاً إضافة Cloud Function.
