# Tokmart

متجر إلكتروني (تسوق، طلبات، دردشة دعم، شحن رصيد، تسجيل دخول عبر Google) مبني بلغة PHP وقاعدة بيانات **MySQL**.

هذا المجلد هو إعادة هيكلة كاملة لنسخة قديمة كانت كل الموقع فيها (الواجهة، لوحة التحكم، الأنماط، والجافاسكربت) داخل ملف PHP واحد ضخم يستخدم SQLite. تمت إعادة تنظيم المشروع بالكامل مع نقل التخزين إلى MySQL.

## ما تغيّر عن النسخة القديمة

- **قاعدة البيانات**: من SQLite إلى **MySQL** (عبر PDO)، مع مخطط جداول منظم في [`database/schema.sql`](database/schema.sql) (أنواع بيانات صحيحة، مفاتيح أجنبية، فهارس، ترميز `utf8mb4` يدعم العربية والإيموجي).
- **تقسيم الكود**: الملف الواحد (حوالي 14,700 سطر) قُسّم إلى:
  - `includes/` – دوال مساعدة (قاعدة البيانات، الجلسات، البريد، الصور، الإشعارات، Google OAuth)
  - `api/` – نقطة API واحدة (`api/index.php`) توزّع كل إجراء إلى ملف مخصص حسب الموضوع (طلبات، منتجات، دردشة...)
  - `assets/css/` و `assets/js/` – كل التنسيقات والجافاسكربت التي كانت مضمّنة داخل HTML أصبحت ملفات خارجية منظمة حسب الوظيفة
  - `admin/` – لوحة تحكم جديدة بالكامل، صفحات منفصلة بدل تبويب مخفي داخل التطبيق
- **حساب المدير**: لا يوجد بعد الآن اسم مستخدم/كلمة مرور افتراضية مكتوبة في الكود. عند أول تشغيل يطلب منك `install.php` إنشاء حساب المدير الخاص بك.
- **الأمان**: تمت إزالة بيانات SMTP و Google OAuth الحقيقية التي كانت مكتوبة مباشرة في الكود القديم؛ تُدخل الآن من لوحة التحكم فقط.
- **إصلاح أخطاء**: تم إصلاح العطل الذي ظهر في `error_log` (استدعاء غير صحيح لـ `SQLite3::exec()` بمعاملين) وعدة تكرارات/أكواد ميتة أخرى وُجدت أثناء المراجعة (نموذج إعدادات الحساب المكرر وغير المفعّل فعلياً، دالة تفعيل كانت تكتب بيانات اعتماد تجريبية في الـ console).
- **نقطة دخول واحدة**: الدومين نفسه (`index.php`) هو تطبيق المتجر الكامل، قبل تسجيل الدخول وبعده — تصفح المنتجات وتسجيل الدخول تظهر مباشرة من نفس الرابط، بدون صفحة تعريفية منفصلة.

## هيكل المشروع

```
tokmart/
├── index.php              # تطبيق المتجر الكامل (تصفح + تسجيل دخول + حساب) — نقطة الدخول الوحيدة للزوار
├── install.php              # معالج التثبيت الأول (قاعدة البيانات + حساب المدير)
├── config/
│   ├── config.sample.php     # نموذج بيانات الاتصال (يُنسخ يدوياً أو يُنشأ تلقائياً عبر install.php)
│   └── config.php            # يُنشأ تلقائياً عند التثبيت (لا يُرفع إلى git)
├── database/schema.sql      # مخطط قاعدة بيانات MySQL الكامل
├── includes/                 # دوال مشتركة (DB، مصادقة، بريد، رفع صور، إشعارات...)
├── api/                      # نقطة الـ API (api/index.php) + معالج لكل مجموعة إجراءات
├── admin/                    # لوحة التحكم (لوحة قيادة، منتجات، تصنيفات، طلبات، مستخدمين، دردشة، شحن رصيد، دفع، إعدادات)
├── assets/css/  assets/js/  # الأنماط والجافاسكربت مقسّمة حسب الوظيفة
└── data/uploads/              # الصور المرفوعة (منتجات، تصنيفات، صور شخصية...)
```

## التثبيت

### المتطلبات
- PHP 8.0+ مع امتدادات: `pdo_mysql`, `gd`, `mbstring`, `fileinfo`, `curl`, `session`
- خادم MySQL 5.7+ أو MariaDB 10.3+

### الخطوات
1. ارفع محتويات هذا المجلد إلى جذر الاستضافة (أو أي مجلد فرعي — التطبيق يكتشف مسار النشر تلقائياً).
2. تأكد أن مجلد `data/` قابل للكتابة من قبل خادم الويب (`chmod -R 755 data`).
3. افتح `install.php` من المتصفح وأدخل:
   - بيانات الاتصال بقاعدة بيانات MySQL (سيتم إنشاء القاعدة والجداول تلقائياً إن لم تكن موجودة)
   - اسم المتجر
   - بيانات حساب المدير الرئيسي (الاسم، البريد، الهاتف، كلمة المرور)
4. بعد نجاح التثبيت سيُنشأ `config/config.php` تلقائياً، ويمكنك الدخول مباشرة إلى `admin/index.php`.
5. من لوحة التحكم ← الإعدادات، أدخل بيانات SMTP الحقيقية (لإرسال أكواد التحقق عبر البريد) وبيانات Google OAuth إن رغبت بتفعيل تسجيل الدخول عبر Google.

> **ملاحظة أمان**: لا يمكن إعادة تشغيل `install.php` بعد نجاح التثبيت طالما `config/config.php` موجود. لإعادة التثبيت من جديد على قاعدة فارغة، احذف هذا الملف يدوياً عبر لوحة الاستضافة أولاً.

### التشغيل محلياً للتجربة
```bash
php -S localhost:8000
```
ثم افتح `http://localhost:8000/install.php`.

## ملاحظات للمطورين

- جميع نداءات الواجهة الأمامية تمر عبر `assets/js/core.js` → `callAPI()` التي ترسل الطلبات إلى `api/index.php?action=...` وتتوقع استجابة JSON بالشكل `{success, message, data}`.
- لوحة التحكم (`admin/*.php`) تُعرض من طرف الخادم مباشرة وتستخدم `assets/js/admin-panel.js` لإرسال إجراءات الحذف/التحديث إلى نفس نقطة الـ API.
- ملفات `.htaccess` المرفقة في `config/`, `includes/`, `database/` تمنع الوصول المباشر عبر المتصفح (تتطلب Apache)؛ تجاهلها إذا كنت تستخدم Nginx وأضف قاعدة مكافئة في إعداد الخادم.
